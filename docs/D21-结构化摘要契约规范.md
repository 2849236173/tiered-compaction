# D21：结构化摘要端到端契约规范

**状态：** 草案，待用户评审确认后方可按此实现与验收
**日期：** 2026-11-03
**范围：** tiered-compaction 第 4 层摘要输入、LLM 请求/响应、检查点提交、摘要事件与持久化回读。

> 本规范是实现前的契约，不代表当前工作区已有改动已获批准。当前实现改动须先逐项对照本规范；不符合项在用户确认后修正，不得以现有代码反过来限制规范。

## 1. 背景与目标

改动前版本中，摘要输入主路径已使用结构化消息，但摘要输出仍存在字符串口径：内置 `_summarizeFnFromCtx` 将 assembler 的多个 text blocks 用 `join("\n")` 合成字符串。官方 basic 则以 `text block[]` 作为摘要正文，原样展开到检查点，并将摘要块数组写入 `compaction/summary` 事件；宿主聊天 UI 也按数组消费 `data.summary`。

目标是确立**一个端到端结构化契约**：会话消息按 role/content 结构传给 LLM；摘要器按 basic 同形结果对象返回块数组；摘要事件和检查点继续保存块数组；不因旧接口、兜底、估算或显示需要而把规范载荷拍平后再传递。

## 2. 不可变原则

1. **结构化消息是摘要输入标准。** 一条消息的 role、顺序和 content 块边界必须保留；不得把多条消息改写为带 `role:` 前缀的一条 user 字符串。
2. **结构化块是摘要输出标准。** `rawOutput` 保留 assembler 的原始块数组；发现 image 输出时按 basic 拒绝本次摘要；规范 `summary` 只包含 basic 规则选出的有序 text blocks，其他非 text 块仍留在 `rawOutput`，不进入摘要正文。纳入 `summary` 的每块内容与块间边界不得合并、重排或静默丢弃。
3. **适配仅发生在边界。** 为兼容旧自定义摘要器，可把其返回的一个字符串包装成单个 text block；进入核心后不再以字符串作为摘要载体。
4. **失败关闭，不静默降级。** 选区中应纳入摘要的消息无法按宿主契约无损重建时，本次摘要必须失败并说明事件 seq/type/原因；不得跳过消息后继续摘要，也不得改为拍平文本。
5. **提交前失败关闭。** 摘要为空、含不支持内容、请求失败、取消、表面变化或压缩收益不足时，不得提交替换检查点。持久化回读属于提交后的完整性验收；若失败，必须将本次验收判失败、保全原始日志/备份并报告恢复方案，不得声称事务已被自动回滚。
6. **估算/展示与规范载荷分离。** token 估算或 UI 展示可以读取 text 字段计算/展示派生文本，但不得将派生字符串回写为 LLM 请求、摘要字段或检查点内容。

## 3. 规范数据契约

### 3.1 摘要输入

规范输入对象：

```js
{
    messages: [
        { role: "system", content: [{ type: "text", text: "..." }] },
        { role: "user", content: [{ type: "text", text: "..." }] },
        { role: "assistant", content: [{ type: "text", text: "..." }] },
        { role: "tool", content: [{ type: "text", text: "..." }] }
    ],
    tools: [...]
}
```

- 每条消息的 `role` 与原消息一致；工具结果按宿主契约使用 `tool` role。宿主定义的消息级字段（如 tool-call id、name 或其他路由元数据）若存在且属于 LLM 请求契约，必须一并保留。
- `content` 规范化为 block 数组。源事件若为纯字符串，只允许在事件到消息的边界包装为 `[{type: "text", text: 原字符串}]`；不得把 block 数组反向拼成字符串。
- 已是数组的 content 按原顺序保留块类型、块值和块边界；不得为构造 prompt 改写成纯文本。
- `session.deriveEventMessage()` 可用时优先使用宿主投影结果；该结果仍须验证并规范化为本节形状。不得丢掉宿主投影产生的有效角色或内容块。
- 老宿主无投影方法时，按宿主事件 schema 的明确映射重建。已知非消息生命周期事件按宿主/basic 规则排除；任何本应纳入的消息事件缺字段、布局未知或无法无损重建时，失败关闭，不跳过。
- 保留消息的原始顺序。system 头按宿主/basic 规则放置且只出现一次。

### 3.2 发给下游 LLM 的请求

- `request.messages` 必须是 3.1 的结构化消息数组，保留选区消息顺序与 block 数组。
- 压缩指令作为单独的末尾 user 消息追加，`content` 为 text block 数组；不得把指令与历史消息拼成一条字符串。
- `tools`、`toolHistory`、`sessionId`、`signal` 等字段遵循宿主/basic 契约；不存在的可选字段不发送为 `undefined`。
- 自定义 `summarizeFn` 收到的 request 也必须遵守上述契约。不得为了适配自定义调用方而改变正式 request 的形状。

### 3.3 摘要器响应

规范响应采用与 basic 同形的结果对象：

```js
{
    summary: [{ type: "text", text: "摘要块" }, ...],
    rawOutput: [...],
    llmStreamCall: true,
    provider: "...",
    model: "...",
    maxTokens: 20000,
    // usage 可选
}
```

`SummaryResult` 的唯一规范摘要字段是 `summary: TextBlock[]`；可选元数据按 basic/宿主契约透传。

- canonical `SummaryResult.summary` 是非空、有序的 text block 数组；至少一个块的 `text.trim()` 非空。
- 内置 LLM 路径保留 `BlockAssembler` 产出的 `rawOutput`；按 basic 规则拒绝 image 输出，并依其 text-only 摘要规则产生 `summary`。一旦成为 `summary`，每个块必须是 `{type:"text", text:string}`，其顺序、内容和边界原样保留。
- `llmStreamCall`、provider/model、maxTokens、usage 等元数据与摘要正文分离；存在时按宿主/basic 规则传递。
- 核心只接收并返回 canonical `SummaryResult`。兼容适配器可在边界接收旧自定义 `summarizeFn` 的 string 或裸 text-block 数组，并立即包装/规范化为 `SummaryResult`；string 包成单个 text block，空字符串和纯空白仍拒绝。进入核心后不得再以字符串作为摘要载体。
- 对象 envelope 中缺失/无效的 `summary`、非 string/non-block-array 兼容输入、image 输出或非法 block，必须明确报错；不得 stringify、静默筛掉不支持的 `summary` 块或生成空检查点。
- 核心、事务与插件返回结果只暴露一个规范摘要字段 `summary: block[]`，不得同时暴露 string `summary` 兼容视图。UI/日志如需文本，只能在消费端临时从块派生，不能回流到规范载荷。

### 3.4 检查点与摘要事件

检查点正文严格为：

```js
[
    { type: "text", text: `${CHECKPOINT_PREAMBLE}\n\n${SUMMARY_OPEN_TAG}` },
    ...summaryBlocks,
    { type: "text", text: SUMMARY_CLOSE_TAG }
]
```

- 中间块逐块展开，顺序、内容与边界不变，不合并为一块。
- `compaction/summary.data.summary` 必须为 `text block[]`；与 basic 一致，`rawOutput`、`llmStreamCall` 及元数据按适用条件写入。
- `user/message` 检查点 `content` 必须为上述块数组；替换边界、`sourceEventSeqs`、`turn`、`compactionId`、`sourceCommandId` 等既有宿主事务字段保持不变。
- `summary` 事件和替换消息必须引用同一逻辑摘要内容；允许 JSON 序列化后对象身份变化，不允许值、顺序或块边界变化。
- 宿主聊天 UI 的 `compactSummary` 以 `Array.isArray(data.summary)` 识别摘要并展示；该字段若写成 string，属于用户可见功能错误。

### 3.5 尺寸估算与错误行为

- 检查点 token 估算按 head、每个摘要 text block、tail 分别累加；不以 `.join()` 创建新的摘要载荷。
- `summaryBlocks` 为空、全空白、包含被 basic 拒绝的 image、格式无效、摘要不小于被取代内容、取消或 surface 不稳定时，事务失败关闭。
- 失败时允许写入既有的 `compaction/start` / `compaction/end` 生命周期记录，但不得写 `compaction/summary` 成功记录或带 `surfaceOp: replace` 的检查点。

## 4. 端到端流程

1. **选择区间**：依现有 surface 位置规则确定 `shadowedSeqs` 与边界，记录稳定性快照。
2. **构造结构化输入**：宿主投影优先；不可用时按事件 schema 重建。校验每条应纳入消息；不能无损重建则停止本次压缩。
3. **构造 LLM 请求**：保留 roles/content blocks、tools、toolHistory、sessionId；追加独立压缩指令块。
4. **执行摘要**：assembler 收集原始块；校验 finish 状态和内容类型；形成 basic 同形的摘要结果对象，`summary` 为 text blocks。
5. **事务前校验**：取消、surface 稳定性、空摘要与压缩收益全部检查通过后才能提交。
6. **构造检查点**：head + 原样 summary blocks + tail。
7. **提交事件**：先写 `compaction/summary`（summary 为 block[]），再写带 replace 操作的 `user/message`，最后写成功 `compaction/end`；沿用既有顺序和关联字段。
8. **持久化回读**：将提交后的日志持久化，使用宿主真实 restore/parser 重新载入，断言事件形状与检查点块序列无损。
9. **UI 消费**：用宿主 UI 对数组载荷的消费逻辑验证摘要标记可读；不得通过改成 string 适配 UI。

## 7. 测试执行要求

1. 单元测试验证数据映射、输入归一、输出块数组、无损展开和 fail-closed 分支。
2. 集成测试必须走真实 `register()` 与宿主 session/event 调用形态；不能只直接调用私有函数，也不能用不会派发事件的静默 append stub 代替宿主行为。
3. 持久化测试使用实际 session persistence/parser 与 restore API，不以 JSON parse 或玩具 schema 校验代替。
4. 用户可见的功能至少包含一条真实宿主会话端到端验证；没有真实宿主验证时，如需先给用户试用，只能归为 beta，并清楚标注“未完全测试通过”。
5. 验收报告逐项列 A–L 的通过/失败/未执行、命令、证据路径与行号；不以总通过数掩盖缺项。

## 8. 风险与发布边界

- 旧自定义摘要器的 string 适配是兼容入口，不是核心契约；必须验证边界之后所有数据形状都回到 blocks。
- 真实 ds-bot capability `parts.js` 在当前机器未定位，故 E 项可先用 basic 同形结果对象验证，但报告必须写明“未直接启动 ds-bot 宿主”；不得声称 ds-bot 实链路已验证。
- 历史 string summary event 对老会话的恢复兼容性尚未在本规范生成时完成验证；J 项是发布门槛，不得通过批量改日志来掩盖。
- 若宿主/basic 的真实 schema 与本规范描述不一致，应先暂停实现、提供源码证据与方案差异给用户确认，不自行发明另一套契约。
