# 重构：对齐原版架构（D18）

**目标**：把「摘要调用」从「拍平成纯文本」改回**原版的完整消息结构重建**，
以复用 provider 的 KV 缓存（省延迟、省成本），并把实现逐项对齐原版契约。

**起因**：交叉审计（gemini-3.8-flash）指出 `contract.js` 把消息序列扁平化后用
`\n` 拼接，剥离了 role 与结构，「导致大模型无法命中任何 KV Cache，
每次摘要都必须全量重算数万 Prompt Token」。

---

## 一、原版架构（事实，已读源码确认）

### 1.1 摘要输入是怎么造的

原版 `dsh-compaction-basic/lib/index.js:buildSummarizationInput`：

```js
function buildSummarizationInput(session, shadowedSeqs) {
  const header = session.requestHeader();
  const head = systemHead(session, session.surface.nodes[0]);
  const system = head === undefined ? null : session.deriveEventMessage(head);
  const regionMessages = shadowedSeqs
    .map((seq) => session.deriveEventMessage(session.eventAt(seq)))
    .filter((message) => message !== null);
  return {
    ...(header?.tools === undefined ? {} : { tools: header.tools }),
    messages: system === null ? regionMessages : [system, ...regionMessages],
  };
}
```

**关键点三条**：
1. 用 `session.deriveEventMessage(event)` 把事件**还原成结构化 message**（保留 role 与 content 块）
2. system 头单独取出，放在消息列表最前
3. **带上 `header.tools`**（工具定义）

### 1.2 摘要请求是怎么发的

原版 `summarizeWithLlm`：

```js
const messages = [...input.messages, deepFreeze({
  role: "user",
  content: [{ type: "text", text: COMPACTION_INSTRUCTION }],
})];
const options = {
  provider: target.provider,
  model: target.model,
  messages,
  toolHistory: agent.session.toolHistory(),     // ← 工具历史
  ...(input.tools === undefined ? {} : { tools: [...input.tools] }),  // ← 工具定义
  maxTokens: config.maxTokens,
  sessionId: agent.session.id,                  // ← 会话标识（缓存键的一部分）
  purpose: "compaction",
  ...(signal === undefined ? {} : { signal }),
};
for await (const chunk of ctx.llm.stream(options)) assembler.push(chunk);
```

**我们的偏差**：只传 `{provider, model, messages, maxTokens, purpose, signal}`，
**缺 `tools`、`toolHistory`、`sessionId`**，且 messages 是两条纯文本。

### 1.3 摘要输出是怎么包装的

原版 `frameSummary`：

```js
[
  { type: "text", text: `${CHECKPOINT_PREAMBLE}\n\n${SUMMARY_OPEN_TAG}` },
  ...summary,
  { type: "text", text: SUMMARY_CLOSE_TAG },
]
```

**我们的现状**：`frameSummaryText` 只拼前缀文本，没有 `SUMMARY_OPEN_TAG` /
`SUMMARY_CLOSE_TAG` 标记——投影层靠这两个标记识别检查点，缺了会影响识别。

### 1.4 其它已对齐项

| 项 | 原版 | 我们 | 状态 |
|---|---|---|---|
| 压缩锁 | `inspectCompactionEntryState` | `inspectCompactionLock` | ✅ 已对齐 |
| 提交前稳定性 | `assertSelectedSpanStable` | `_assertSpanStable` | ✅ 已对齐 |
| 选区按位置切片 | `nodes.slice(startIdx, endIdx+1)` | 同 | ✅ 已对齐 |
| `turn` 字段 | `lifecycle = {compactionId, turn: owner}` | 同 | ✅ 已对齐 |
| overflow 强制恢复 | `selectCompactableRange(..., 0)` | `retainOverride: 0` | ✅ 已对齐 |
| 摘要重试 | `compactionRetries` | 同 | ✅ 已对齐 |
| `finishError` 判定 | 按 `finish.kind` 分派 | `finishErrorOf` | ✅ 已对齐 |
| **摘要输入结构** | **结构化 message + tools + toolHistory** | **拍平纯文本** | ❌ **本次要改** |
| **检查点标记** | **OPEN/CLOSE 标签** | **只有前缀文本** | ❌ **本次要改** |

## 二、重构后的流程（每一步请求）

### 步骤 1：选区（不变）

`compactIfNeeded` / `compactNow` → `_selectRange` → `{start, end}`
输出：表面上的一段位置区间（配平、不劈开 tool 对、受 retain 约束）。

### 步骤 2：构造摘要输入（**改**）

`_runTransaction` 调用新模块 `buildSummaryInput(session, shadowedSeqs)`：

```
输入：session, shadowedSeqs
1. header = session.requestHeader()
2. head = session.eventAt(surface.nodes[0])
   system = head?.type === "system/message" ? session.deriveEventMessage(head) : null
3. regionMessages = shadowedSeqs
     .map(seq => session.deriveEventMessage(session.eventAt(seq)))
     .filter(m => m !== null)
4. messages = system ? [system, ...regionMessages] : regionMessages
5. tools = header?.tools
输出：{ messages, tools? }
```

**兜底**：若 `session.deriveEventMessage` 不存在（旧宿主/测试桩），
退回当前的文本拼接方案，并记一条 warn。**不能因为宿主老版本就崩**。

### 步骤 3：发摘要请求（**改**）

`summarize(input, agent, signal)` 改为：

```
options = {
  provider, model,
  messages: [...input.messages, { role:"user", content:[{type:"text", text: COMPACTION_INSTRUCTION}] }],
  toolHistory: session.toolHistory?.(),        // 有则传
  tools: input.tools,                          // 有则传
  maxTokens: RESERVE_TOKENS,
  sessionId: session.id,                       // 有则传
  purpose: "compaction",
  signal,
}
```

### 步骤 4：校验与包装（**改包装**）

- `finishErrorOf(assembler.finish)` 判失败（已有）
- 取 `text` 块拼成摘要文本（已有）
- `frameSummary(summary)` 改为**带 OPEN/CLOSE 标签**：
  ```
  [ {text: `${CHECKPOINT_PREAMBLE}\n\n${SUMMARY_OPEN_TAG}`},
    {text: summary},
    {text: SUMMARY_CLOSE_TAG} ]
  ```

### 步骤 5：提交事务（不变）

`compaction/summary` → `user/message`(surfaceOp replace) → `compaction/end`

## 五、风险与取舍（写在前面，免得验收时争论）

| 风险 | 说明 | 应对 |
|---|---|---|
| KV 缓存收益未实测 | 我们只验证「结构传对了」，没法在本地测 provider 侧缓存命中率 | 验收只断言请求结构；缓存收益留待线上观察 |
| `toolHistory` 可能很大 | 传入完整工具历史会增大请求 | 原版也这么传，先对齐；若线上发现过大再做裁剪 |
| 旧宿主兜底路径质量较低 | 文本拼接丢掉结构，KV 缓存仍命中不了 | 明确记 warn，不静默降级 |
| `deriveEventMessage` 是内部 API | 若宿主版本变动可能失效 | 用 `?.` 调用 + 存在性判断，缺失即走兜底 |
