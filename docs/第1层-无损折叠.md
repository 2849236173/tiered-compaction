# 第 1 层 · 无损折叠

**目标**：把重复内容的体积压下来，且**能逐字节还原**。零 LLM 成本。

## 问题

工具输出里大量重复是常态——构建日志的 heartbeat、轮询输出、同一命令反复执行的结果。它们占据上下文，但信息量极低。

朴素的「去重」会丢信息。这一层的约束是：**折叠必须可逆**。

## 算法

```
输入：原始文本
  │
  ├─ 逐行扫描，找出连续重复 ≥3 次的块
  │
  ├─ 每个块替换为：首行 + 一行折叠标记
  │     …[folded Nx]
  │
  ├─ 生成逆变换记录 runs：
  │     每项记录「原文行号 → 重复次数 → 首行内容」
  │
  └─ 净收益判据：折叠后字节数必须小于原文，否则放弃本次折叠
```

## 净收益判据

折叠本身也要占字节（标记、记录）。如果省下来的不足以抵消标记开销，折叠等于白做。

判据用**字节**而不是字符数：中文字符 UTF-16 长度 1、UTF-8 字节 3，用字符数判断会让中文内容的实际体积被低估三倍，导致该折叠的没折叠、或不该折叠的折了反而变大。

## 可逆性

逆变换记录 `runs` 里每项记三个字段：

| 字段 | 含义 |
|---|---|
| `start` | 该重复块在**原文中的真实行号** |
| `count` | 重复次数 |
| `lines` | 被折叠的实际内容 |

还原时按 `runs` 逐块重建，并**校验 `start` 与重建位置一致**——记录被篡改时校验失败，而不是静默还原出错内容。

这条校验拦四类篡改：改 `runs`、改 `count`、改 `start`、伪造整个记录。

## 折叠原文必须落盘

折叠记录只在内存里，进程重启就没了。所以**折叠发生时，原文同时写入存档**，谱系表记录「原位置 → 存档路径 + digest」。

这样即使进程重启，原文仍可还原。早期实现只在谱系里写一个 `fold:1` 字符串而不是文件路径，等于折叠后原文永久丢失——这是被修掉的一个 P0。

## 与第 2 层的关系

折叠后如果**仍然**超过落盘阈值（8KB），落盘的是**折叠后的文本**，但存档里必须有**折叠前**的原文。

否则第 2 层的 SHA-256 校验会为第 1 层的信息损失盖章——校验通过，内容已丢。

## 验收要点

| 项 | 标准 |
|---|---|
| 可逆 | 折叠后还原，与原文逐字节一致 |
| 篡改检测 | 改 `runs` / `count` / `start` 任一处，还原失败 |
| 净收益 | 折叠后字节数 < 原文，否则不折 |
| 原文落盘 | 折叠记录带存档路径与 digest |
| 中文安全 | 中文重复行折叠后仍可逐字节还原 |
