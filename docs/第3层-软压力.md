# 第 3 层 · 软压力

**目标**：窗口压力上来时，先用零成本手段腾空间。零 LLM 成本。

## 两个阈值

```
压力 < 70%        不动
      ≥ 70%        插入提醒（不改历史）
      ≥ 80%        开始驱逐
```

**70% 只提醒**：写一条日志提示模型收束任务，**不往会话里塞消息**——插提醒本身要耗 token，在压力已经上去的时候做这件事是反向操作。

**80% 开始驱逐**：按优先级从低到高移除可重放内容。

## 驱逐优先级

| 优先级 | 类型 | 理由 |
|---|---|---|
| 1 | `bash` `pwsh` `edit` `write` | 执行类，结果可由重跑或读文件恢复 |
| 2 | `read` `grep` `glob` | 读取类，重跑即恢复 |
| 3 | `system-reminder` | 系统提示，可重建 |
| 永不 | `todo` `goal` `plan` `user-message` `summary` | 用户意图与任务状态，丢了不可重建 |

## 只驱逐可恢复的

驱逐是一条**窄路**：

- **可重放**（`read` / `grep` / `glob`）→ 可直接驱逐，模型重跑即可拿回内容
- **不可重放但已存档**（`bash` / `edit` / `write`，且原文已在存档）→ 可驱逐，附存档路径
- **不可重放且无存档** → **绝不驱逐**

早期实现无条件按优先级表驱逐，`bash` 的输出被删掉却没有任何存档——永久丢失。这是被修掉的一个 P0。

## 净收益判据

驱逐也会产生标记与谱系记录。如果被驱逐内容还没标记长，驱逐等于让上下文变大。

所以驱逐前算净收益：**省下的字节必须大于新增标记的字节**，否则跳过。

## 与第 1-2 层去重

驱逐记录的序号必须与第 1-2 层的处理记录**分开记**。

早期实现共用同一个 `done` 集合，导致第 3 层认为某个内容「已处理」而跳过，或反过来把第 1-2 层的记录当成已驱逐——每步追加两条事件，会话日志无限膨胀。

## 跨会话隔离

去重集合必须**按会话隔离**（`WeakMap<session, {done, evicted}>`）。

`seq` 是**会话内**序号，每个会话都从 0 开始。用一个进程级 `Set` 记账的结果是：第一个会话正常，其后所有新会话的 `seq` 全部命中旧记录 → 一条都不处理 → 压缩静默失效，且零报错。

## 验收要点

| 项 | 标准 |
|---|---|
| 阈值行为 | <70% 不动、70-80% 只提醒、≥80% 驱逐 |
| 永不驱逐 | todo/goal/plan/user-message/summary 零丢失 |
| 无存档不驱逐 | 不可重放且无存档的内容必须保留 |
| 净收益 | 越驱越大时跳过 |
| 跨会话 | 新会话的 seq 不继承旧会话的去重记录 |
| 与第 1-2 层去重 | 驱逐记录与折叠/落盘记录分开 |
