> 版本：v0.5（smart-compact v0.5.3 源码已读：§8 R38-1 定稿、§9-6 槽位竞争预案、挂载探测改 construction-catch） · 2026-10-26

## 0. 背景与问题

DSH 当前只有「80% 触发 → LLM 摘要」一步到位的默认压缩（dsh-compaction-basic 0.2.1-rc.2），实测 22,690 次摘要调用中 2,462 次被 2,048 token 上限截断过半。Bot 执行慢的根源之一是上下文常驻 20 万+ token，LLM 每轮都在为早已过时的工具输出付注意力和费用。

**本插件的目标**：把「一步摘要」改造成「四层递进」，让 90%+ 的上下文瘦身在**零 LLM 成本**的前三层完成，有损 LLM 摘要只做最后兜底。

## 1. 总体架构：四层管线

```
工具输出产生
    │
    ▼
┌─ 第 1 层 无损折叠层（lossless-fold）─────────────┐
│ 日志/grep/diff 重复块折叠（保留首尾 + 重复计数）    │  零 LLM 成本
│ 每次折叠生成逆变换记录，运行时自校验（抽样还原比对） │
└──────────────────┬───────────────────────────┘
                   ▼
┌─ 第 2 层 落盘层（spill-to-disk）─────────────────┐
│ >8,000 字符的工具输出整体落盘（SHA-256 校验）      │  零 LLM 成本
│ 上下文只留 ≤1,500 字符预览 + 存档路径             │
└──────────────────┬───────────────────────────┘
                   ▼
┌─ 第 3 层 软压力层（soft-pressure）────────────────┐
│ 70% 窗口：插入提醒（不改历史）                     │  零 LLM 成本
│ 80% 窗口：驱逐易失内容（见 §3 优先级表）           │
└──────────────────┬───────────────────────────┘
                   ▼
┌─ 第 4 层 有损摘要层（lossy-summarize）────────────┐
│ 压力阈值 = 窗口 − max(16k, 5%窗口) − 摘要预留(≤20k)│  LLM 调用
│ 摘要预算提前预留，杜绝截断死循环                    │
└──────────────────────────────────────────────┘
```

**旁路管线（确定性，不调 LLM）**：目标切换清理（goal-switch purge）
- 触发：仅显式信号——用户或主 Bot 显式宣告新目标（结构化事件，不做语义自动识别）
- 动作：旧目标的 todo/goal/plan 关键状态打包成结构化胶囊并入新上下文；过程性内容（大输出、中间产物）归档到会话目录
- 与四层管线独立挂载，可单独开关

## 2. 保真三原则（贯穿全部层）

1. **每层留恢复机制**：第 1 层逆变换记录；第 2 层 SHA-256 + 全量文件；第 3 层被驱逐项记原始位置可重放（read/grep/glob 重跑即恢复）；第 4 层摘要前全量存档
2. **被取代引用记谱系，不静默删**：任何内容被折叠/落盘/驱逐/摘要取代，在谱系表登记「原位置 → 新位置 → 取代者」，可审计可回溯
3. **压缩系统自身有熔断器 + 仲裁器**：单层异常（如落盘连续失败）自动降级跳过该层并告警；仲裁器决定内容归属哪层，避免多层重复处理

## 3. 软压力层驱逐优先级（80% 触发时）

| 优先级 | 内容类型 | 处理 | 恢复方式 |
|---|---|---|---|
| 1（先驱逐） | bash/pwsh/edit/write 大输出 | 驱逐，谱系表记录 | 不可重放，依赖落盘存档 |
| 2 | read/grep/glob 输出 | 驱逐，标记「可重放」 | 重跑工具即恢复 |
| 3 | 系统提醒/临时注入 | 直接清除 | 无需恢复 |
| 永不清理 | todo/goal/plan/用户消息/摘要节点 | 保留 | — |

**口径定死（M5 验证后，v0.5）**：① 驱逐验收口径 = 「从同一集合中移除全部命中项」（A3 判 PASS 看集合正确，不要求移除顺序；实现按节点顺序，效果等价）；② 落盘阈值 8k 的 size 口径 = **UTF-8 字节数**（`Buffer.byteLength`），非字符数。

## 4. 与 dsh-compaction-basic 的关系（并存策略）

- **不修改、不替换**已装插件；本插件注册为独立 Cordis 服务
- **服务位铁律（M2 接口验证结论，详见附录 A）**：同一 `ctx.compaction` 服务位**不可双注册**——`enabled=true` 时 profile 侧必须只启用其一（本插件或 basic）；`enabled=false`（默认）时本插件仅注册自检服务，不占服务位，与 basic 完全并存
- 开关设计：配置项 `tieredCompaction.enabled`（默认 false）
- 接口对齐：实现 `CompactionEngine`（`ctx.compaction` 服务位），触发/保留/摘要策略全部自有；压力读数复用 `ctx.tokenMeter`

## 8. R38 外部参照并入（2026-10-26，侦察员专项扫描，PO 并入）

三条同域参照，按用途归位：

**R38-1 dsh-smart-compact v0.5.3（8★，DSH 同域真插件——产品化最直接参照，源码已读、定位定稿 2026-10-26）**

源码位置：`H:\github\_pkg-smart-compact\package\`（npm tgz 解包目录，非 git 仓库，不提交）。lib/ 12 模块。

- **路线差异（定稿）**：它是**替换派**——Codex 式硬换窗（rollover）：阈值 0.85 触发 + wrap-up 缓冲带（阈值到阈值+buffer 之间提醒一次让模型写 ctx_notes）+ 整窗归档 + STALE 新鲜度门（归档时间戳与日志比对，锚点不背书过期状态）+ windowGeneration 窗代号。实现上是 `extends BasicCompactionEngine` 只覆写两个钩子（`summarize` 返回固定零模型交接模板、`compactIfNeeded` 三带策略），注册与压缩事务全继承 basic。我们是**递进派**——四层处理留在同一窗口、零 LLM 瘦身优先、LLM 摘要只兜底。两者争同一服务位但形态不同：换窗 vs 就地瘦身。
- **挂载探测（必须抄）**：construction-catch 探测——构造器 provide() 与已有 owner 冲突时 catch 住、从报错解析槽位持有者、主动让位降级为 tools+reminder 模式继续跑。**严禁 `ctx.get('compaction')` 探针**：它会强制实例化懒声明的引擎、把槽占掉反噬自己（headless 实测踩过）。我们 M2 确认的「服务位替换」路线要按此方式实现探测。
- **同构物对照**：它的 ctx_notes（跨窗工作笔记，write/append/read/search/list 五动作）与我们 M4 目标切换胶囊同构——胶囊是事件驱动打包（显式宣告触发、带 todo/goal/plan 结构化状态、确定性），ctx_notes 是模型自写自由文本分段。**取舍：保留我们的胶囊**，取它 HANDOFF_LINE_MAX=80 行交接上限作胶囊体积参照值。
- **可借鉴细节**：①engine-state.json 运行时探针（挂载决策/换窗计数/降级标志落盘可查）——对 A7 熔断器告警面是好范式，可补落盘探针；②`ctx.isolate('toolResultPruner')` 隔离滞后第三方服务、防其拖垮压缩事务的防御手法；③deriveNotesFreshness「探针任何形态只降级、绝不编造」的诚实契约。

**R38-2 hermes-vcc-engine（14★，零模型规则压缩）**
- 实证数据：0.055s vs 8 分钟；**召回 91.0% > 全窗口 87.1% > stock 76.2%**——摘要优于全文 = 去噪效应，支撑「摘要不是纯损失」的设计论据

**R38-3 hermes-warm-compaction（65★，缓存复用路线）**

- **落地**：M4 有损层设计须对比两案——DSH compaction-basic 已有前缀缓存复用，本插件 A4a 预算方案 vs warm-compaction 缓存复用方案，择优或混合；摘要输入不得先截断（规避丢中部）

## 附录 A：M2 接口验证结论（程序员实测，2026-10-25）

1. **接管语义确认为「服务位替换」**：宿主接口 `@deepseek-ai/dsh-compaction` 导出
   `CompactionEngine extends Service`，构造即占用 `'compaction'` 服务名；basic 的
   `BasicCompactionEngine` 同样 `extends CompactionEngine` 并由插件入口静态导出。
   本插件完整接管触发时机的方式 = 实现同类 Service 并在 enabled 时注册进
   `ctx.compaction` 服务位，**无需 hook 更底层 agent-loop**（风险项 1 就此关闭）。
2. **并存铁律的精确化**：`enabled=true` 时若 basic 同时注册，同一服务位会冲突
   （先后顺序取决于 loader，行为不可控）——开关语义修订为 **profile 侧只启用其一**；
   本插件 `enabled=false`（默认）时只注册自检服务 `tieredCompaction`，与 basic
   完全并存、行为与纯 basic 一致（支撑 A6）。
3. **压力读数来源**（风险项 2 收口）：basic 依赖 `ctx.tokenMeter`（dsh-token-meter
   服务位）做压力测量与 surface 对齐；第 3/4 层复用同一服务位，无需另接私有接口。
4. **模块形态**：宿主插件均为无构建链单文件 ESM + JSDoc（basic 即 `lib/index.js`
   单文件）；本插件遵循同构，`src/index.js` 直出，无需 tsc/bundler。
5. **本地开发解析**：ESM 不走 NODE_PATH；仓库内建指向宿主
   `G:\DSH Desktop\resources\app\node_modules` 的 junction（已 gitignore），
   测试与加载验证经此解析。
6. **骨架验证**：`node --test test/index.test.js` 3/3 过（模块可加载、enabled
   双态注册行为正确）；宿主侧实际加载验证留给 M6（运维沙箱 profile）。
