## 0. 背景与问题

DSH 当前只有「80% 触发 → LLM 摘要」一步到位的默认压缩（dsh-compaction-basic 0.2.1-rc.2），实测 22,690 次摘要调用中 2,462 次被 2,048 token 上限截断过半。Bot 执行慢的根源之一是上下文常驻 20 万+ token，LLM 每轮都在为早已过时的工具输出付注意力和费用。

**本插件的目标**：把「一步摘要」改造成「四层递进」，让 90%+ 的上下文瘦身在**零 LLM 成本**的前三层完成，有损 LLM 摘要只做最后兜底。

## 1. 总体架构：四层管线

```
工具输出产生
    │
    ▼
┌─ 第 1 层 无损折叠层（lossless-fold）─────────────┐
│ 日志/grep/diff 重复块折叠（保留首尾 + 重复计数）    │  零 LLM 成本
│ 每次折叠生成逆变换记录，运行时自校验（抽样还原比对） │
└──────────────────┬───────────────────────────┘
                   ▼
┌─ 第 2 层 落盘层（spill-to-disk）─────────────────┐
│ >8,000 字符的工具输出整体落盘（SHA-256 校验）      │  零 LLM 成本
│ 上下文只留 ≤1,500 字符预览 + 存档路径             │
└──────────────────┬───────────────────────────┘
                   ▼
┌─ 第 3 层 软压力层（soft-pressure）────────────────┐
│ 70% 窗口：插入提醒（不改历史）                     │  零 LLM 成本
│ 80% 窗口：驱逐易失内容（见 §3 优先级表）           │
└──────────────────┬───────────────────────────┘
                   ▼
┌─ 第 4 层 有损摘要层（lossy-summarize）────────────┐
│ 压力阈值 = 窗口 − max(16k, 5%窗口) − 摘要预留(≤20k)│  LLM 调用
│ 摘要预算提前预留，杜绝截断死循环                    │
└──────────────────────────────────────────────┘
```

**旁路管线（确定性，不调 LLM）**：目标切换清理（goal-switch purge）
- 触发：仅显式信号——用户或主 Bot 显式宣告新目标（结构化事件，不做语义自动识别）
- 动作：旧目标的 todo/goal/plan 关键状态打包成结构化胶囊并入新上下文；过程性内容（大输出、中间产物）归档到会话目录
- 与四层管线独立挂载，可单独开关

## 2. 保真三原则（贯穿全部层）

1. **每层留恢复机制**：第 1 层逆变换记录；第 2 层 SHA-256 + 全量文件；第 3 层被驱逐项记原始位置可重放（read/grep/glob 重跑即恢复）；第 4 层摘要前全量存档
2. **被取代引用记谱系，不静默删**：任何内容被折叠/落盘/驱逐/摘要取代，在谱系表登记「原位置 → 新位置 → 取代者」，可审计可回溯
3. **压缩系统自身有熔断器 + 仲裁器**：单层异常（如落盘连续失败）自动降级跳过该层并告警；仲裁器决定内容归属哪层，避免多层重复处理

## 3. 软压力层驱逐优先级（80% 触发时）

| 优先级 | 内容类型 | 处理 | 恢复方式 |
|---|---|---|---|
| 1（先驱逐） | bash/pwsh/edit/write 大输出 | 驱逐，谱系表记录 | 不可重放，依赖落盘存档 |
| 2 | read/grep/glob 输出 | 驱逐，标记「可重放」 | 重跑工具即恢复 |
| 3 | 系统提醒/临时注入 | 直接清除 | 无需恢复 |
| 永不清理 | todo/goal/plan/用户消息/摘要节点 | 保留 | — |

## 4. 与 dsh-compaction-basic 的关系（并存策略）

- **不修改、不替换**已装插件；本插件注册为独立 Cordis 服务
- 开关设计：配置项 `tieredCompaction.enabled`（默认 false），开启后接管 `ctx.compaction`；关闭时 basic 照常工作
- 并存验证标准：两插件同装、开关切换，会话不崩、token-meter 读数连续
- 接口对齐：实现 `@deepseek-ai/dsh-compaction` 的 `CompactionEngine`（`ctx.compaction` 服务位），触发/保留/摘要策略全部自有

## 6. 验收标准（写死，测试员按此验证）

| # | 验收项 | 标准 |
|---|---|---|
| A1 | 无损折叠 | 折叠后信息可逆：抽样 10 组折叠内容做逆变换还原，与原文逐字节一致 |
| A2 | 落盘层 | >8k 输出全部落盘，SHA-256 校验通过；上下文预览 ≤1.5k 字符 |
| A3 | 软压力 | 70% 只提醒不改历史；80% 驱逐后 todo/goal/plan/用户消息零丢失。**触发百分比读数来源 = token-meter 服务接口（M2 接口验证一并确认，结论写附录；若接口不可用则改用自算 token 估计并在附录记录口径）** |
| A4a | 有损层·预算 | 摘要调用参数中预留值 ≥ 设计值（插件侧，可硬验证） |
| A4b | 有损层·截断 | 按 A8 同一 fixture 实测截断率，相对基线（enabled=false）下降，具体阈值 M1 定 |
| A5 | 目标切换 | 显式宣告新目标后：胶囊包含旧目标 todo/goal/plan 状态；过程内容归档；全程零 LLM 调用 |
| A6 | 并存开关 | enabled=false 时行为与纯 basic 基线一致（**基线 = M2-M4 期间抓取的 basic 行为记录：触发时机、摘要输出形态、落盘路径，存 `test/basic-baseline.md`**）；切换开关会话不崩 |
| A7 | 熔断器 | 人为制造落盘失败，插件降级跳过该层并告警，主流程不受阻 |
| A8 | 效果度量 | **fixture = 仓库 `test/` 内固定重放脚本 + 样例会话（M3 前由程序员随第 1-2 层交付）；token 读数来源同 A3 口径；方法 = 同一 fixture 分别跑 enabled=false/true 各一次，记录上下文 token 均值差 ≥30%、LLM 摘要调用次数差 ≥50%** |
| A9 | 版本管理 | git log 显示 feature 分支开发 + 合并 local-main，无远程操作记录 |
| A10 | 谱系表 | 任一内容被折叠/落盘/驱逐/摘要取代后，谱系表可查到「原位置 → 新位置 → 取代者」三元组；抽样 10 条逐一对得上实物 |

## 8. 风险与开放问题

1. **CompactionEngine 接口私有性**：`ctx.compaction` 的替换语义需程序员实测——插件能否完整接管触发时机，还是要 hook 更底层的 agent-loop？M2 先做接口验证再写业务
2. **token-meter 对接**：压力百分比读数来源需确认（dsh-token-meter 的服务接口）
3. **截断问题的根修**：2,048 截断发生在 basic 插件内部还是 LLM 层？若在本插件可控范围内则 A4 可硬保证，否则只能降低触发频率
4. **pi-maestro-flow 18 模块的取舍**：只移植思想（四层+三原则+目标切换），teammate-relay/relevance/evidence-index 等深度绑定 Pi 的不搬
