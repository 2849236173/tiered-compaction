## 二、P0 发现与修复

### P0-1：摘要输入丢失 83.5% 内容

**文件**：`src/contract.js` `_runTransaction`

**缺陷**：真实宿主里消息内容的存放位置不统一，而代码只读其中一种：

| 事件类型 | 内容位置 | 旧实现 |
|---|---|---|
| `user/message` | `data.content` | ✅ 读到 |
| `assistant/message` | `data.message.content` | ❌ 读成空 |
| `tool/result` | `data.message.content` | ❌ 读成空 |

**实测量化**（真实会话 `session-e350d45d`，14 条事件）：

- 旧逻辑抽出 **45,838 字**
- 实际内容 **277,328 字**
- 丢失 **83.5%**
- 其中 `tool/result` 的 **224,556 字一个字都没进摘要**

**后果**：摘要只看得到用户说了什么，看不到助手做了什么、工具返回了什么。
而工具结果恰恰是压缩的主要对象。产出的是「知道要做什么、不知道做到哪」
的半截检查点，续做的模型会重复已完成的工作——**比不压缩更糟**。

**修法**：新增 `textOfEventForSummary`，两种存放位置都试；
`tool-call` 保留工具名+参数（「做过什么」的唯一线索）；
`reasoning` 明确丢弃（对续做无用且极占篇幅）。

**验证**：修复后同一会话抽取量 45,838 → **367,742 字（+702%）**。
新增 7 条测试，反向验证 5 条变红。

**提交**：`2d489812` / 合并 `5e52f52e`

### P0-2：观察者并发重入导致重复处理

**文件**：`src/tool-result-observer.js` `handleEvent`

**缺陷**：去重标记 `done.add(seq)` 在 `await processToolOutput(...)` **之后**才执行，
中间存在真实的竞态窗口：

```
调用 A: done.has(1)? 否 → 进入 → await（挂起）
调用 B: done.has(1)? 否 → 也进去 → await（挂起）
两者各自完成 → 写两条 replace 事件
```

**触发条件**（都不罕见）：宿主重放事件、观察者重复注册、宿主不 await 钩子。

**实测复现**：并发两次 → `processToolOutput` 被调用 **2 次**、替换事件 **2 条**。

**后果**：同一位置被替换两次、多写存档文件、健康自检计数翻倍（计数会骗人）。

**修法**：进入前先占位（`add` 再 `await`）；失败时回滚占位
（否则该 seq 永久被跳过，重放也无法补救）。

**验证**：新增 4 条测试，反向验证 2 条变红。

**提交**：`4d71e58a` / 合并 `dcab21f1`

## 三、核查后判定「不是问题」的三项

这一节同样重要——避免为了凑数而误报。

### 1. 钩子拿不到 `agent`？—— 不是问题

我一度以为 `agent/pre-step` 的载荷不含 `agent`。查 `dsh-agent/lib/index.js:243`：

```js
const fused = (payload) => ({ ...payload, agent });
```

宿主**确实注入**了 `agent`。是我看漏了一层包装，判断错误。

### 2. `estimateTokens = length / 4` 低估中文？—— 可接受

实测真实会话（373,053 字符，其中中文 23,493 个）：

- `length / 4` = 93,264
- 按中文 0.75 token/字重估 = 105,010
- 偏差 **1.13 倍**

中英混合场景下偏差不大，且摘要前后用的是同一公式，比较结果会抵消。
**不构成缺陷**。

### 3. `CircuitBreaker` 打开后仍然执行？—— 我测错了

`exec` 在熔断时返回 `null`（约定「调用方应跳过该层降级」），
我在测试里把 `null` 当成了「执行了」。状态机本身正确：
3 次失败 → open → 冷却后 half-open → 成功恢复 closed。

## 五、P3（不影响正确性，未修）

### P3-1：压缩锁检查是 O(n) 全量扫描

`inspectCompactionLock` 从事件流尾部倒序扫到找到 `compaction/start|end` 为止。
若整段会话没有任何压缩事件（最常见情况），会扫完整条日志。

实测：5 万条事件 2ms、50 万条约 20ms。每次 `pre-step` 都会调一次。

**影响**：长会话下每步多 20ms，不致命但会线性恶化。
**未修理由**：需要引入索引/记忆化，改动面大于收益，且当前会话规模下无感。

### P3-2：折叠兜底判断用字符数，与逐行判据的字节口径不一致

`lossless-fold.js:70` 的 `folded.length >= text.length` 用字符数，
而逐行判据用字节数。

**影响**：极端情况下（中文短行）会保守地少折一次，**不会产生错误产物**。
**未修理由**：试了多种构造都难以触发实际损失，改为字节口径更一致但收益极小。
