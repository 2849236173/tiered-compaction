# 架构

分层压缩插件挂在宿主 `ctx.compaction` 服务位上，接管「何时压、怎么压」。

交互式架构图：[架构图.html](架构图.html)（浏览器打开，可缩放）

## 总览

```
工具输出产生
    │
    ▼
结果观察者（session/event 同步派发）
    │
    ▼
第 1 层 · 无损折叠 ── 重复行折叠，附逆变换记录        零 LLM
    │  仍超阈值
    ▼
第 2 层 · 落盘 ────── >8KB 原文存档，上下文留头尾预览  零 LLM
    │  压力上升
    ▼
第 3 层 · 软压力 ──── 70% 提醒 / 80% 驱逐可重放内容    零 LLM
    │  到阈值
    ▼
第 4 层 · 有损摘要 ── 重放前缀 + 预算预留，1 次 LLM 调用
```

另有一条旁路：**目标切换清理**——显式宣告新目标时，把旧目标的 todo/goal/plan 打包成结构化胶囊，过程内容归档，全程零 LLM。

## 三条贯穿约束

### 1. 每层留恢复机制

| 层 | 恢复方式 |
|---|---|
| 折叠 | 逆变换记录 + 折叠原文存档 |
| 落盘 | 完整文件 + SHA-256 校验 |
| 驱逐 | 记原始位置，`read`/`grep`/`glob` 重跑即恢复 |
| 摘要 | 摘要前全量存档 |

### 2. 被取代引用记谱系

任何内容被折叠、落盘、驱逐、摘要取代，都在谱系表登记「原位置 → 新位置 → 取代者」，附 SHA-256 便于对实物。可审计、可回溯，不静默删。

### 3. 自身有熔断与仲裁

- **熔断器**：单层连续失败达阈值后打开，冷却后半开试探，成功则恢复。失败降级为「跳过该层，主流程拿原文继续」，绝不阻断对话。
- **仲裁器**：保证一份内容只归一层处理，避免同一内容被折叠又落盘。

## 关键设计决策

### 摘要输入重放会话前缀

摘要请求不是「把选区内容拼成一段文本」，而是**重放会话前缀**：system 头 + 选区内每条事件的投影消息 + tools 定义，末尾追加一条压缩指令。

这样摘要请求的 messages 是正常对话请求的**严格前缀**，provider 侧的 KV 缓存可直接复用。若拍平成纯文本，role 与块结构全丢，缓存一次都命中不了，每次摘要重算整个前缀。

详见 [第4层-有损摘要](第4层-有损摘要.md)。

### 选区按位置切片，不按 seq 数值

会话表面的 `seq` 不单调——一次 `replace` 会把新事件放回被替换节点的原位置。用数值区间过滤会漏节点，并让首尾比对必然失败。

### 去重与状态按会话隔离

`seq` 是会话内序号，每个会话从 0 开始。进程级共享去重集合会让第一个会话之后的所有新会话静默失效——零报错、`stats` 冻结。

## 契约对接

插件实现宿主 `@deepseek-ai/dsh-compaction` 的 `CompactionEngine` 抽象：

- 注册为 `ctx.compaction` 服务（**同一服务位不可双注册**，启用时须停用 `compaction-basic`）
- 读取 `ctx.tokenMeter` / `ctx.llm` / `ctx.sessions`
- 通过 `session.append` 写入 `compaction/start`、`compaction/summary`、`compaction/end` 与检查点 `user/message`

事件与数据结构见 [数据结构](数据结构.md)。
