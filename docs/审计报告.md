## 0. 结论先行

插件**模块级实现基本合格，但「接到真实宿主」这条链有系统性缺口**：三处「配置/代码存在但运行时不生效」的实锤（P1-P3），一处 D15 遗留的生效性问题升级为最高优先级（P0）。单元级验收（A1-A12）全过掩盖了宿主路径的挂空。

| 级别 | 数量 | 性质 |
|---|---|---|
| P0 | 1 | 插件从未在任何真实会话执行过（D15 切换只完成配置面） |
| P1 | 1 | 第 1-2 层真实宿主零执行（无工具输出入口） |
| P2 | 2 | 第 3 层驱逐/提醒空转；overflow 恢复钩子未注册 |

| P4 | 2 | 缺 Config schema、compactNow 缺 flush |

## P0【漏·最高】插件从未在真实会话执行过

- **出处**：D15 B 路线（安装记录 §11）
- **事实**（运维对接员实测，2026-10-26 15:4x）：扫描全部会话 `agentPreset`——本会话/E-sub2api/kuajin-web/H-temp 全是 `standard`，study-story 两个是 `code`。**没有任何会话跑过 ptc-tc**。`selectedDefault: ptc-tc` 已切、`preset-ptc-tc` 已注册，但 preset 由**会话创建时**决定，存量会话不自动切换。
- **结论**：漏。D15「切换完成」是配置面完成；「生效」要等一个新建会话选中 ptc-tc。A12 探针是裸 Context 级，测不了这条。
- **修补建议**：用户新建任一会话（选中 ptc-tc）后，读会话 `agentPreset` 字段 + 日志确认插件加载，即完成 P0 验证；配套在 D15 维护护栏里加「生效检查」一条。
- **工作量**：用户动作 1 次 + 检查 5 分钟。

## P1【漏·宿主路径】第 1-2 层真实宿主零执行

- **出处**：设计稿 §1「工具输出产生→无损折叠→落盘」；§2 原则 1/2
- **事实**（PO+程序员+Chief 三方独立复核一致）：src 内唯一 `ctx.on` 是 contract.js:156 的 agent/pre-step（压缩触发钩子）；`processToolOutput`（第 1-2 层唯一入口）仅 test/m45-wiring.test.js 调用；`config.archiveDir` 收下后零消费（contract.js 全文仅 L58 注释提及）。连带缺失：**摘要前无全量存档**（保真原则 1 第 4 层要求，contract.js `_runTransaction` 无 spill/archive 调用）、**宿主路径无谱系记录**（原则 2，contract.js 事务不碰 lineage）。
- **结论**：漏。tiered-archive 不出现是必然，不是「还没触发」。
- **修补建议**（程序员给出两档，待 Chief 定）：
  - **保守版（推荐先做，0.5-1 天）**：`session/event` 观察者对 `tool/result` 只做预计算+落盘+谱系登记，**表面改动为零**——不碰 replace，规避 tool-pairing 配平与 replace 契约风险；上下文瘦身收益留到 P1 全量版再收。
  - **全量版（1.5-2 天，风险中高）**：观察者做替换事务（append `compaction/prune` 影子定价 → `tool/result` surfaceOp replace）。机制参考已挖实：basic 的 pruner 三件套（basic lib:926 取服务、:929/:943 调用）。风险：tool-pairing 配平扰动 + 「replace 不得再 replace」契约撞车。
- **配套补**：`_runTransaction` 摘要前全量存档 + 谱系登记（原则 1/2 宿主路径，0.5 天内）。

## P2-1【错·宿主路径】第 3 层驱逐广播零消费者、提醒只进日志

- **出处**：设计稿 §3 驱逐优先级表、A3
- **事实**（PO 挖出，程序员核实成立）：contract.js:113 的 80% 驱逐只是 `ctx.emit("tiered-compaction/evict", …)` 广播，src 内无任何监听者注册；70% 提醒只 `logger.info` 不进会话表面。对照 basic：它是**同一事务内同步 prune 落地**，无广播模式——广播是本插件自创的、无人消费的机制。
- **结论**：错。第 3 层在真实链路同样空转（与 P1 同根源：实现挂在「层内」没挂「宿主路径」）。
- **修补建议**：pre-step 钩子内（contract.js:156 已有挂点）直接调 `evictVolatile` 并按 basic 三件套落地（或并入 P1 修补的同一观察者）；驱逐必须产生会话表面效果或明确降级为「仅记录」，二选一写死。
- **工作量**：并入 P1（不单独计）。

## P2-2【漏·契约】overflow 恢复的 agent/request-error 钩子未注册

- **出处**：basic 契约（basic lib:861-887）
- **事实**（程序员核实）：basic 用 `agent/request-error` 钩子做真实溢出后的恢复压缩（retry 语义 + replaceGeneration 校验）；contract.js 只注册了 agent/pre-step，**未注册 request-error**——真实宿主里 provider 报溢出错误后，本插件的 overflow 恢复路径永不触发。
- **结论**：漏。context-overflow 触发在实际溢出场景下没有恢复能力。
- **修补建议**：照 basic lib:861-887 注册 request-error 钩子（含 retries 记账 + replaceGeneration 判断）；连带补 `agent/status` idle 清理与 `session/event` assistant/message 清理（overflowRetries 的双钩子清理，见 P3-3）。
- **工作量**：0.5 天。

## P3-1【错·层内】落盘阈值用字符数而非 UTF-8 字节数

- **出处**：A2「>8k 输出全部落盘」；R38-2「Factory 评测文件追踪最弱项」引申口径
- **事实**（程序员核实，PO 复核代码一致）：spill-to-disk.js:39 `text.length <= threshold` 判断用 **JS 字符数**；L45 落盘时 size 却用 `Buffer.byteLength(text, "utf8")`。非 ASCII（中文 1 字符 = 3 字节）场景：8,000 汉字 ≈ 24KB 输出**不会被落盘**。
- **结论**：错。1 行修复（L39 改 byteLength）+ 单测补非 ASCII 用例。
- **工作量**：0.5 小时。

## P3-2【错·层内】_selectRange 缺 tool-pairing After 校验

- **出处**：contract.js:216（「不拆 assistant tool-call/result 对」）
- **事实**（程序员核实）：选区尾部只向**前**配平（toolPairingBalancedBefore），未校验所选 end 是否把配对**后**半截留在了替换区间外——特定边界下可能把 result 留下、call 压掉。
- **结论**：错（边界条件触发）。修复 + 边界用例。
- **工作量**：2 小时。

## P3-3【实现有但设计没写】overflowRetries WeakMap 只增不清

- **出处**：contract.js:63（自注「照 basic 的 WeakMap 口径」）
- **事实**（程序员核实）：basic 有双钩子清理（agent/status idle + session/event assistant/message，basic lib:853-860）；contract.js 未注册这两条，WeakMap 只增不清。
- **结论**：错（设计声称对齐但缺半截）。并入 P2-2 修补。
- **工作量**：并入 P2-2。

## P4-1【漏·契约】缺 static Config schema

- **出处**：basic 契约对比表（安装记录 §9.3）
- **事实**（程序员核实）：basic 有 `static Config = z.object({...})`；contract.js 无。配置错误（如 archiveDir 类型）将在运行时才暴露。
- **结论**：漏（防御性）。补 schema，工作量 1 小时。

## P4-2【漏·契约】compactNow 无 sessions.flush

- **出处**：basic 契约对比
- **事实**（程序员核实）：basic 压缩前 flush sessions；contract.js compactNow 直接入事务。并发/持久化时序在真实宿主未验证。
- **结论**：漏（待真实验证定严重度）。补 flush + m6h 实测，工作量 2 小时。
