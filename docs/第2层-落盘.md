# 第 2 层 · 落盘

**目标**：超长工具输出整体存到磁盘，上下文只留一份能定位原文的预览。零 LLM 成本。

## 问题

一次构建日志、一次 `grep` 全仓搜索、一次测试输出，动辄几十万字符。全留在上下文里，窗口很快被吃满；直接丢弃，模型再也拿不到这些信息。

解法：**原文完整存档，上下文留路标**。

## 触发条件

超过 **8192 字节**（UTF-8）才落盘。

为什么按字节不按字符：`"中文".length === 2`，但 UTF-8 是 6 字节。用字符数判断会让 8000 个汉字（约 24KB）逃过阈值，落盘层在中文场景下等于失效。

## 预览预算

上下文里留下的预览上限 **5120 字符**，头尾比 **4:1**：

```
原文 10,433 字符
  ↓
┌──────────────────────────────┐
│ 头部 ~4096 字符（命令、参数、路径）│
│ …[中间省略 6000 字符，见存档]    │
│ 尾部 ~1024 字符（结论、错误码）   │
└──────────────────────────────┘
```

**为什么是 5120 / 4:1**：对齐 DSH 官方 `dsh-compaction-tool-result-pruner` 的预算（`headChars 4096` + `tailChars 1024`）。官方判断是开头信息量更大——命令、参数、路径都在开头；尾部保留结论行（`exit code`、`pass/fail` 计数、汇总行）。

**为什么可以只留 5120 而不更多**：原文 100% 存档，模型随时可 `read` 回来。官方 pruner 是「剪掉即丢」，所以它必须多留；我们多存了一层，就可以少留。

## 存档格式

| 项 | 内容 |
|---|---|
| 路径 | `<archiveDir>/<会话标识>-<seq>.txt` |
| 内容 | 原始文本（UTF-8，逐字节） |
| 校验 | SHA-256 记录在谱系表 |
| 防覆盖 | 同名文件已存在时追加 `-2`、`-3`，绝不静默覆盖 |

**为什么绝不覆盖**：存档是压缩后唯一能还原原文的东西。被覆盖时谱系表仍指向该路径，回读会拿到别人的内容且无任何告警——属于越用越坏。

## 还原

`restoreSpilled(path, expectedSha256)`：

1. 读文件
2. 算 SHA-256
3. 与期望值比对，不一致则报错

**UTF-8 往返检查**：落盘前验证 `Buffer.from(text).toString() === text`。JS 字符串可含孤立代理项（非法 UTF-16 序列），写文件时会被替换成 `U+FFFD`，导致「SHA 校验通过、内容已被改」。这道检查在落盘前完成，不通过则拒绝写。

## 预览的安全边界

切分不能按 UTF-16 code unit 裸切：

- **代理对**：emoji 等字符占 2 个 code unit，切断会产生孤立代理项 → 写文件变 `U+FFFD`
- **CRLF**：切断会让头部以孤立 `\r` 结尾、尾部以孤立 `\n` 开头

切点落在代理对中间时挪一位；尾部以孤立 `\n` 开头且前一位是 `\r` 时也退一位。

## 验收要点

| 项 | 标准 |
|---|---|
| 逐字节还原 | 中英、emoji、CRLF、纯换行都能还原 |
| 阈值口径 | 8k 汉字（约 24KB）必须落盘 |
| 不覆盖 | 同名文件存在时追加序号，原文件内容不变 |
| 篡改检测 | 改动存档内容后还原失败 |
| 预览不超限 | 含省略标记在内的总长 ≤ 5120 |
| 中文安全 | 预览切分不产生孤立代理项或孤立 CRLF |
